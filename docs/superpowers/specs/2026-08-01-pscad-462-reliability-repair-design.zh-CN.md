# PSCAD 4.6.2 可靠性修复设计

**日期：** 2026-08-01
**状态：** 已批准，待实施
**适用后端：** `LegacyBackend` / PSCAD 4.6.2 x64 / `mhrc.automation` 1.2.4

## 目标

修复 PSCAD 4.6.2 真机验收确认的七个功能缺陷和两个设计问题，同时保持现有 53 个 MCP 工具的名称、参数和安全确认规则不变。

修复完成后，MCP 只有在 PSCAD 命令成功且后置条件成立时才返回成功。厂商命令返回 `success=false`、目标文件不存在、状态未改变或进程未清理时，必须返回结构化错误。

## 范围

本轮修复：

1. `create_case` 和 `create_library` 无法创建可用工程；
2. `save_project_as` 在 PSCAD 返回失败时仍报告成功；
3. `get_run_status` 固定返回 `unknown`；
4. `enable_component` 和 `disable_component` 未改变可验证状态；
5. `find_empty_space` 可能返回与现有对象重叠的矩形；
6. 已接线元件无法由删除工具可靠删除；
7. `pause_simulation` 向 stdout 输出 `Pause`，可能污染 MCP stdio；
8. “工程设置”实际调用 PSCAD 全局设置并忽略 `project_name`；
9. `repair_connection` 可能遗留 MCP 自己启动的 PSCAD 进程。

本轮不新增工具，不增加仿真集、场景、清理工程或远程控制能力，也不修改 modern 后端的公开行为。

## 已有真机证据

基线五组 PSCAD 4.6.2 x64 验收通过：只读、元件与 Canvas 修改、构建、仿真与输出、PSOUT 解析。

扩展验收确认：

- 参数读取、写入、范围校验、元件移动、端口查询、端口连接、镜像、单个未接线元件删除、未接线元件批量删除、全部构建和仿真集操作可工作；
- `create_case` / `create_library` 首先触发 XML 整数序列化错误，绕过该错误后仍未生成工程文件；
- `save_project_as` 对三种目标路径均收到 `success=false`，但服务层报告成功；
- `get_run_status` 返回 `{"status": "unknown", "progress": null}`；
- 元件启停返回成功，但没有产生可验证的启停状态；
- 空位搜索结果与已知元件矩形重叠；
- 删除已连接元件失败，但删除未连接元件通过；
- 暂停操作调用成功，但捕获到 stdout 文本 `Pause\n`；
- 所有验收进程最终均已清理，原始 PSCAD 示例未修改。

## 总体方案

采用后端内定点修复：工具层和 `PscadService` 保持稳定，版本专属行为集中在 `LegacyBackend`。不修改已安装的 `mhrc.automation` 包，也不全面重写厂商 XML 协议。

```text
现有 MCP 工具（名称和参数不变）
                 │
            PscadService
                 │
        LegacyBackend 4.6.2
        ├─ 命令响应校验
        ├─ 文件与状态后置条件
        ├─ 非阻塞运行状态桥接
        ├─ Canvas 几何与连接处理
        └─ 进程所有权安全恢复
```

## 命令结果与错误模型

Legacy 后端增加统一的内部响应校验：

- XML 响应缺失或 `success` 不是 `true`：`PSCAD_COMMAND_FAILED`；
- PSCAD 声称成功但文件、对象或状态未出现：`POSTCONDITION_FAILED`；
- 4.6.2 无法提供所需能力且没有安全回退：`CAPABILITY_UNAVAILABLE`；
- 路径、确认参数和连接状态继续沿用现有错误结构。

错误详情包含 PSCAD 操作名、项目名、目标路径或元件 ID，以及经过截断和 JSON 标准化的响应信息。原始代理、XML 节点和异常对象不越过后端边界。

## 工程创建

`Workspace.create_project()` 在当前 4.6.2 环境不能可靠生成文件，因此不把其返回的代理视为成功证据。

实现使用随包安装的最小空白工程模板：

- 一个经 PSCAD 4.6.2 打开和保存验证的空白 `.pscx`；
- 一个经 PSCAD 4.6.2 打开和保存验证的空白 `.pslx`；
- 模板只包含用户创建的空白工程结构，不复制厂商示例内容；
- 模板作为包数据安装，开发环境和已安装入口行为一致。

创建流程：

1. 服务层完成工作区路径和覆盖确认检查；
2. 把对应模板复制到目标路径；
3. 以保留格式的方式改写工程根节点名称和必要的输出名称；
4. 解析 XML，确认根节点类型、名称和后缀一致；
5. 让 PSCAD 加载目标文件；
6. 重新查询项目列表，确认名称和类型；
7. 失败时删除本次新建且未通过验收的目标文件。

## 另存为

另存为优先调用 PSCAD 原生 `Project.save_as()`，但必须检查 XML 响应和目标文件。

当前 4.6.2 原生命令失败时使用受控文件回退：

1. 保存当前工程并确认源文件存在；
2. 复制源工程到目标路径；
3. 改写目标工程内部名称及与工程名绑定的输出名称；
4. 解析目标 XML；
5. 让 PSCAD 加载目标工程；
6. 确认目标文件、项目名和项目类型；
7. 任一步失败时清理本次产生的不完整目标。

已有目标仍由 `confirm=true` 控制。覆盖前不删除目标；写入临时同目录文件并完成验证后再替换，避免中途破坏已有文件。

## 运行、状态、暂停和停止

`run_project` 改为发送非阻塞运行命令，使单工作线程能够继续处理状态、暂停和停止请求。工具仍返回“已启动”，不等待完整仿真结束。

`get_run_status` 把 4.6.2 回调式 `Project.get_run_status()` 桥接为有界异步调用：

- 从响应中标准化状态和进度；
- 回调超时返回明确错误，不固定伪造 `unknown`；
- 完成、停止和失败状态清理内部运行记录。

暂停绕过厂商包装函数中直接写 stdout 的语句，发送等价 PSCAD 命令并检查响应。停止使用相同的响应校验。由于 4.6.2 的暂停和停止作用于所有运行工程，返回文本和文档必须明确这一语义。

## 工程设置

`get_project_settings` 调用目标项目的 `Project.parameters()`。

`set_project_settings` 优先调用 `Project.set_parameters()`：

- 返回 `False` 时报告参数无效；
- 返回成功后重新读取所有被修改的键；
- 任何值不一致均返回 `POSTCONDITION_FAILED`。

PSCAD 全局 `PSCAD.settings()` 不再由这两个工具调用。

## 元件启用和禁用

4.6.2 使用专用项目层实现可验证启停：

- 层名固定为 `PSCAD_MCP_DISABLED`；
- 首次禁用时创建该层并将状态设为 `disabled`；
- 禁用元件时把元件加入该层；
- 启用元件时把元件移出该层；
- 已处于目标状态时操作幂等；
- 每次操作后从工程 XML 或等价命令结果验证层成员和层状态。

不得继续通过不存在的 `enabled` 参数声称成功。工程原有其他层不被修改。

## 已连接元件删除

删除前先建立完整删除计划：

1. 校验所有目标元件存在；
2. 读取所有目标元件的端口绝对坐标；
3. 枚举 Canvas 导线，找出端点与目标端口相连的导线；
4. 去重相关导线和元件 ID；
5. 先删除导线，再删除元件；
6. 重新读取 Canvas XML，确认所有目标元件和相关导线消失。

批量删除在开始变更前完成全部校验。删除过程中失败时报告已经删除和尚未删除的 ID，不声称原子回滚。

## 空位搜索

4.6.2 回退算法使用 Canvas XML 的 `x`、`y`、`w`、`h` 构造占用矩形。缺少尺寸时采用保守默认尺寸，不能把对象简化为单个锚点。

候选位置：

- 对齐 18 单位 Canvas 网格；
- 由 `near` 向外分层搜索；
- 使用矩形相交判断并保留安全间距；
- 返回值必须在再次读取 Canvas 后仍不与占用矩形相交；
- 搜索边界内无空位时返回 `NO_EMPTY_SPACE`。

## 连接修复和进程所有权

`repair_connection` 根据当前后端的 `owns_process` 处理：

- MCP 自己启动的实例：先调用正常退出，确认已断开，再重置执行器和重新选择后端；
- 非自有实例：仅断开，不终止进程；
- 退出或断开失败：停止修复，不启动第二个实例；
- 重连失败：返回结构化错误并保持连接元数据一致。

Legacy 4.6.2 后端继续明确为“启动新自动化实例”，不声称能够复用用户已经打开的 4.6.2 实例。

## 测试与验收

每个真机缺陷先增加会在旧实现上失败的自动测试，然后实施修复。

自动测试至少覆盖：

- `success=false` 不得变成成功；
- 工程创建和另存为的文件、XML、加载后置条件；
- 回调状态的成功、超时和异常；
- 非阻塞运行允许后续状态、暂停和停止进入执行器；
- stdout 保持为空；
- 工程参数无效键和回读不一致；
- 专用禁用层的创建、幂等和成员验证；
- 已连接及未连接元件的单个/批量删除；
- 矩形碰撞、网格对齐和无空位；
- 自有与非自有进程的修复路径；
- 53 个工具继续唯一注册。

真机验收全部使用 `D:\PSCAD-Workspace\acceptance` 下新的时间戳副本，覆盖：

1. 新建 case 和 library 后重新加载；
2. 另存为并重新加载；
3. 非阻塞运行、状态、暂停、停止；
4. 工程参数读取、写入和恢复；
5. 元件禁用、启用和保存后验证；
6. 已接线元件删除；
7. 空位搜索和创建后无重叠；
8. repair 后只有一个新实例，最终进程数为零；
9. 现有五组回归验收。

## 安全与清理

- 不修改公共 PSCAD 示例；
- 只操作时间戳副本和明确目标文件；
- 不使用通配方式终止 PSCAD；
- 只退出由当前验收或 MCP 明确拥有的实例；
- 不修改厂商 wheel 或 PSCAD 安装目录；
- 不自动删除验收证据目录；
- 失败时报告所有可能残留文件和进程。

## 完成标准

必须同时满足：

- 新增缺陷测试在旧实现上失败、修复后通过；
- 完整自动测试零失败；
- `compileall`、依赖检查和 `git diff --check` 通过；
- 53 个工具且名称唯一；
- 上述九组扩展真机验收通过；
- 原有五组真机验收通过；
- 验收结束 PSCAD 进程数为零；
- Git 变更仅包含本轮设计、实现、测试、模板和必要文档。
