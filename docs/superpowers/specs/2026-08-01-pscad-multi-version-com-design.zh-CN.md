# PSCAD 多版本 COM 连接设计

> 本设计已被 `2026-08-01-pscad-dual-backend-design.zh-CN.md` 替代。真实验收确认 PSCAD 4.6.2 需要 `mhrc.automation` legacy 后端，而不是现代 `mhi.pscad` 启动协议。

**日期：** 2026-08-01

## 目标

让 PSCAD MCP 的连接流程能够在当前安装的 PSCAD 4.6.2 上工作，同时保留对 PSCAD 5.x 的兼容性。服务器必须保持 PSCAD 调用串行执行、保留有界超时机制，并避免验收失败后遗留自动化进程。

## 已确认的问题

当前 `PscadAdapter.attach_local()` 通过 `RobustExecutor` 调用 `mhi.pscad.application()`。在 Windows 上，该工作线程没有初始化 COM 单元，导致 `mhi.pscad` 使用的 WMI 查询在连接或启动 PSCAD 之前失败。

在主线程调用相同接口时，`mhi-pscad` 3.1.2 虽然可以检测到 PSCAD 4.6.2，但其默认最低版本是 5.0，因此拒绝启动 4.6.2。显式指定版本后可以打开 PSCAD 4.6.2，证明第二个问题来自版本选择，而不是 PSCAD 安装本身。

## 架构设计

### 支持 COM 的串行执行器

`RobustExecutor` 继续作为所有 PSCAD 调用的统一执行边界。它使用单一工作线程，并在执行 PSCAD 或 WMI 操作前初始化 Windows COM。所有调用保持串行，因为不能假设 PSCAD 自动化代理对象具有通用线程安全性。

COM 支持采用可选导入方式，使单元测试、非 Windows 环境和文档相关操作仍能正常启动。如果可以导入 `pythoncom`，工作线程会在生命周期内初始化一次 COM。执行器超时并重置后，新工作线程会重新初始化 COM。

### 支持版本选择的 PSCAD 适配层

`PscadAdapter` 负责连接和版本选择，不再依赖 `mhi.pscad.application()` 中可能随版本变化的默认启动策略。

连接顺序如下：

1. 调用 `mhi.pscad.connect()`，尝试复用已有的、已启用自动化接口的 PSCAD 实例。
2. 如果没有可连接的实例，调用 `mhi.pscad.versions()` 获取已安装版本。
3. 应用用户提供的可选配置条件。
4. 选择最高的已安装版本；相同版本同时存在时优先选择 64 位。
5. 使用明确的 `version`、`x64` 和 `minimum` 参数调用 `mhi.pscad.launch()`。

这样既能支持 PSCAD 4.6.2，也能支持 PSCAD 5.x，而且不依赖 MHI 软件包默认最低版本的变化。

## 配置项

连接层识别以下可选环境变量：

- `PSCAD_MCP_VERSION`：指定准确的 PSCAD 版本，例如 `4.6.2` 或 `5.0.2`。
- `PSCAD_MCP_X64`：取值为 `true` 或 `false`；未设置时优先选择 64 位。
- `PSCAD_MCP_LAUNCH_TIMEOUT`：正数形式的启动超时时间，单位为秒。

无效配置会产生明确、可操作的错误。如果指定的版本或位数未安装，服务器会返回检测到的可选版本，而不会静默改用其他安装。

## 实例归属与清理

适配层会记录当前实例是连接到已有 PSCAD，还是由 MCP 新启动。断开 MCP 时只清理代理对象，并在执行器不健康时重置执行器，不会自动终止 PSCAD。现有的 `quit_pscad` 工具仍是正常流程中唯一主动请求退出应用程序的操作。

验收程序只能关闭自己启动的实例。发生失败时，清理程序必须先核对可执行文件路径和自动化启动参数，再终止相应进程。

## 错误处理

连接错误需要区分以下情况：

- 未安装 `mhi-pscad`；
- 环境变量配置无效；
- 用户指定的版本未安装；
- 没有检测到任何 PSCAD 安装；
- 连接已有实例失败，随后启动新实例也失败；
- 执行器超时或处于不健康状态。

错误应保留原始异常作为原因，同时向 MCP 客户端返回简洁、可理解的说明。

## 测试方案

自动化测试使用注入的 MHI 和 COM 模块替身，覆盖以下行为：

- 工作线程第一次执行调用前初始化 COM；
- 执行器重置后重新初始化 COM；
- 启动新实例前优先连接已有实例；
- 自动选择最高版本，并优先选择 64 位；
- 显式选择 PSCAD 4.6.2；
- 选择 PSCAD 5.x；
- 无效配置以及指定版本不可用；
- 启动参数包含所选版本和明确的最低版本。

单元测试和 MCP 工具注册测试通过后，使用有界的真实环境验收程序，通过 MCP 的 `get_local_pscad` 路径连接 PSCAD 4.6.2，读取健康状态、许可证、项目列表、设置和仿真集名称，然后显式退出由测试启动的实例。最后检查进程列表，确保没有遗留 PSCAD 或验收 Python 进程。

- 本轮连接修复不加载、构建、保存或仿真任何项目。
- 不增加新的建模或结果分析工具。
- 当前没有 PSCAD 5.x 安装，因此不会宣称已经完成 5.x 端到端验证；5.x 兼容性通过模拟 API 合约测试验证。
